# Subagent harness 首批优化设计

- 日期：2026-09-09
- 输入：`docs/research/2026-09-09-subagent-harness-next-optimizations.md`
- 授权：用户明确要求按推荐方案实现并验证；不提交、发布或修改本机模型配置。

## 目标与边界

减少重复探索和不必要的上下文变化，用真实记录而非子代理退出速度评价收益。采用研究报告的渐进顺序：先离线基线、关键证据交接和稳定前缀；并发/effort/cap 仅在实测有依据后调整。本轮不引入全量 fork、调度器、额外模型判断或新观测平台。

## 实现合同

1. 在现有 session-stats 目录提供 Bun 离线报告入口，消费既有 JSONL。显式输入路径/日期范围；输出聚合指标与覆盖率，不输出任务正文、工具参数、密钥。缺失数据保持 unknown，正常结束不等于验证通过。
2. 分开报告文件跨度、assistant 活跃墙钟、模型 TTFT/生成、工具计时、spawn queue。重叠子任务不直接相加成父端到端耗时；无法证明最终验收时明确未测得。
3. 子代理 prompt 将稳定规则和角色合同置于动态任务材料之前，保留项目默认环境块、schema 覆盖、只读与工作树权限。fresh/revive 不引入不同合同。
4. 复用 task.context / artifacts 交接验收、关键原始证据、状态版本、失败尝试和验证归属；worker 只对过时或缺失信息重读，reviewer 不继承作者未经证实的判断。不开新 schema/参数，不复制完整父历史。
5. 不恢复强制 yield、无条件 stop hook 或周期性进度轮次。

## 已确认与未确认

已确认：现有指标与结果关联结构、当前子代理模板动态context位于静态合作规则之前、本地并发基准mock边界。未确认：该顺序在真实provider上造成多少缓存损失，最近三天交接/协调/effort对端到端时间的因果贡献。实现只消除可验证的结构问题并增加测量入口，不凭假设调生产参数。

## 验证

- 离线分析测试：旧/坏/缺失记录、失败与未知、父子识别、工具配对、重复读取、并行跨度不相加、输出不包含对话正文。
- 提示测试：同角色不同动态材料具有相同静态前缀；动态信息仍存在；worker/review/schema/空context和恢复场景保持合同。
- 集成：相关现有测试、bun check、包bundle构建；新鲜会话报告与既有本地并发mock benchmark，分别注明证据性质。
- 实网资格测试尝试使用既有入口和安全凭据；无可用凭据/模型或样本不足时如实记录，不用mock代替质量/缓存实测。

研究输入已获用户批准；没有正式独立根因评审，不虚构PASS。离线统计不改变执行行为；提示排序不改变权限和结束协议。完整fork和自动调参因尚无本地收益证据不在默认变更内。
